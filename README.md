# Lazy Acres Vacation Planner

**Production:** https://tpoirier1969.github.io/Vacation-Planner/

A shared, trip-focused vacation workspace for Tod and Donna. Hosted as a static site on GitHub Pages from `main`.

## Current features

- Create and reopen trips, with a persistent trip workspace until **Exit trip**.
- Explore a Leaflet/OpenStreetMap map with a USGS aerial-imagery toggle, map click/right-click to save places, and colored category markers.
- Search locations and businesses through Geoapify's geocoder and partial-name Places search (with Nominatim fallback), or discover nearby businesses/points of interest by category and distance in miles; both workflows can add an Idea or start a scheduled Itinerary entry. List cards, discovered-marker popups, and direct map-click place selections now show descriptions. Source priority: Geoapify/OpenStreetMap text, explicitly linked Wikipedia article, explicitly tagged Wikidata item (linked Wikipedia extract or its English description), then an honest OpenStreetMap feature-type explanation; unknown stays unknown. OpenStreetMap place hours, contact/website and external Google Maps review searches are shown when available. Details are lazily fetched and cached; the app never invents review scores or substitutes unverified same-name Wikipedia entries.
- **Responsive masthead:** enlarged transparent roadside-sign logo on the left, active trip summary and controls on the right, with connection status in the same header. The redundant standalone trip hero has been removed to reclaim vertical space; tablet/phone layouts scale the sign down and wrap trip controls.
- **v0.6.22 route section editor:** Each adjacent pair of route points appears as a numbered driving section with an explicit Remove section / Reconnect control. Disconnecting a section retains its endpoints and any saved stops, while road calculations use only connected runs. Routes can be ordered and labeled as day, outbound, or return. Click a drawn route to select its corresponding section group, or focus a section and use Delete; Undo supports section toggles. Recalculate after changing connected roads. Live authenticated map acceptance is still required.
- **Routes** share the Explore sidebar with Discover Nearby. Create multiple named routes per trip, set start and destination by typed search or map click, add road-shaping via points or dedicated stops by clicking roads, reorder/remove/Undo points, and add mapped Ideas or itinerary entries as stops. Calculate roads, mileage, estimated driving time, and per-leg estimates with the existing Geoapify free account. Store named alternatives, compare distance/time, hide/show the active route, specify start/end dates and local times, and select balanced/short/fewer-turn routes and toll/highway/ferry avoidance preferences. Routes sync through Supabase; no second offline store. Estimates do not account for live traffic or time spent at stops.
- **v0.6.25 mobile workspace:** A compact trip header and fixed phone navigation replace long desktop-style scrolling. Map results use a simple Expand / Collapse full-screen panel; Ideas and Itinerary each have mobile-first quick-entry forms. Business discovery supports a miles radius, paged results and partial business-name matches using smaller Geoapify category queries. Both search entry points offer separate **+ Idea** and **+ Itinerary** actions; the itinerary action prepopulates its existing scheduling form without creating an unwanted Idea. The route editor now stacks or wraps fields, route comparisons, waypoints and driving sections to stay within narrow iPhone screens. The static layout fixture was browser-tested at 320, 375, 390, 430 and 720 px with visible nonzero-width route controls and no horizontal overflow. Live signed-in iPhone acceptance and two-account verification are still pending.
- **v0.6.24 route and map corrections:** Outbound/Return route labels now save as schema-valid `journey` rows with `preferences.journeyDirection` rather than invalid database `route_kind` values. Journey and Day are also supported. Independent temporary map visibility checkboxes hide/show Ideas, Itinerary, and Routes without modifying records. The route editor can import mapped itinerary activities for its selected start day, skipping already-linked stops and sorting new stops by time while leaving itinerary dates and times untouched.
- **Restaurants in Discover Nearby** must have restaurant/cafe/fast-food/food-court classification or corresponding OpenStreetMap dining tags. A generic "catering" tag alone cannot qualify; a business with event catering and a restaurant is included.
- **Ideas** are things under consideration (places, events, experiences, activities, etc.), grouped by category with a selectable category filter and counts. Each Idea has an inline category selector so misclassified discoveries can be corrected without losing ID, location, or notes; full editing remains available. An Idea may retain a possible date, local time, and fixed-event constraint and need not have map coordinates.
- **Itinerary** contains decided activities, with an unscheduled group for plans without a date. Choosing an Idea for the Itinerary hides it from consideration while preserving its map/source details; moving it back restores the Idea. Directly adding an itinerary item does not create an unwanted Idea.
- Itinerary entries support local start/end times, must-do priority, fixed dates, lodging checkout, booking status, confirmation number, and booking link.
- Edit research notes and manage/edit a 14-category packing checklist.
- Share trip data across authorized household accounts through Supabase Realtime table notifications, with a 15-second fallback refresh and refresh when the page becomes active.

## Data and access

**Authoritative data store:** the existing shared Supabase project, tables `vacation_trips`, `vacation_routes`, `vacation_places` (the historical table name for considered Ideas), `vacation_itinerary`, `vacation_notes`, and `vacation_packing`. Household access is controlled by `vacation_members` and database RLS. An existing restricted `auth.users` trigger automatically enrolls preapproved household email addresses after successful email verification. Supabase Auth persists sign-in sessions in the browser; the browser may also remember the UI map-style preference and current tab's trip-navigation state. These are **not** alternate trip-data stores.

New trip-data edits are sent to Supabase and acknowledged before the app displays **Saved to Supabase**. Incoming changes update visible trip lists without reloading; an editor refuses to save if its record has visibly changed in the meantime. This is not a transactional simultaneous-edit lock. Failed saves are visibly flagged, retain unsaved state only in the current page's memory, and offer **Retry save**; leaving/reloading with pending writes shows a browser warning. Offline editing is not a durable supported workflow. Historical browser-local records are not automatically imported.

The independent household Shopping & Packing app remains separate. Trip packing is stored in the planner's own Supabase table.

## Running and deploying

The repository maintains one `last-working-copy` branch as a rollback snapshot, updated after owner-accepted live releases. Do not accumulate backup branches or duplicate hosted apps.

No build or package install is required. The entrypoint is `index.html`; `version.js` is the only canonical release-version value. `itinerary.js` and `ideas.js` own domain-level timing, validation, and consideration rules; `discovery-details.js` owns source-backed descriptions, explicit Wikipedia and Wikidata lookups, truthful category fallback, opening-hours formatting, and external review-search URLs; `routes.js` owns route editing, Geoapify routing and map waypoints. The entrypoint uses that value to version CSS/JS resource URLs and display the version. GitHub Pages deploys from `main`/root.

Dependencies: pinned Leaflet 1.9.4, pinned Supabase JS 2.97.0, Geoapify free-tier API. Map, place search, and discovery require internet access and can be rate-limited.
